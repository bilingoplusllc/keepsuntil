# KeepsUntil — как это устроено

Справочник сроков хранения еды на данных **USDA FoodKeeper**. 302 страницы продуктов по 1 500+ слов каждая, поиск по словам имени и ключевым словам источника НА КАЖДОЙ странице, три вычисленных рейтинга, указатель, рубрики, календарь дат. Ноль зависимостей, ноль сетевых запросов у готовой страницы, скрипт один на страницу — поиск везде плюс календарь на странице продукта, — и он необязательный: без него поле поиска сменяется ссылкой на указатель, а календарь — тем же диапазоном словами.

```bash
python fetch_data.py --verify   # снимок данных тот самый и дата на сайте — его
python render.py                # собрать dist/
python gates.py                 # 79 гейтов по собранному И по диску
python gates.py --selftest      # каждый гейт ломается нарочно и обязан покраснеть
```

## Единица публикации — ПРОДУКТ, а не строка источника

Замер 05.09.2026 по текущему снимку: **100 имён из 466 несут больше одной
строки, и в одноимённых группах сидят 292 строки из 658** — 44% источника.
`Leftovers` — три строки (с мясом, без мяса, пицца), `Milk` — пять, `Eggs` —
три, `Beef` — десять.

Пока страница заводилась на СТРОКУ, каждая такая строка была почти дословным
близнецом соседней, и гейт близнецов честно выбрасывал их все. Отсюда корпус
без головы ниши: ни листовков, ни молока, ни яиц, ни курицы — при том, что
предфильтр они проходили. **Гейт работал правильно. Неверна была единица.**

Теперь одноимённые строки сливаются в один продукт с несколькими
СОСТОЯНИЯМИ. `/leftovers/` — не три невыпущенных близнеца, а одна страница с
тремя ответами.

| Правило слияния | Почему так |
|---|---|
| слияние по **имени**, не по подзаголовку | `Chicken parts` и `Chicken` — разные продукты; `Milk / lactose-free` и `Milk / ultra-pasteurized` — один |
| у каждого состояния **свой подзаголовок** в подписи поля и в заголовке группы бланка | окна у состояний разные: без имени три окна подряд читаются как одно |
| пустое и тощее состояние вливается **прочерком**, а не выбрасывается | `Milk / plain or flavored` несёт одну ячейку и ни одного срока вне морозилки — и всё равно печатается |
| сигнальное поле считается **по ячейкам того вида, за который страница говорит** | у продукта с несколькими видами состояния — это разная еда, и «кончится первым» через все виды выбирало не то окно, а не тот продукт |
| отношение печатается только **внутри одного состояния** | двенадцать месяцев сгущённого молока, делённые на пять дней вскрытого лактозного, — не сравнение |
| соседи — **другие продукты** | прежде соседями продукта оказывались его же состояния: тупик и близнец одним движением |
| рубрика берётся у **первой** строки имени, числа — у первой, **у которой они есть** | сгущённое молоко лежит в бакалее, и продукт `Milk` уезжал туда вместе с ним |

`MIN_FACTS` из **допуска** стал порогом **подробности**: он прореживает блок
сравнений и больше не снимает страницу. Порог на входе — «есть срок вне
морозилки и есть с кем сравнить».

Порядок рассмотрения начинается со **спроса** (`render.HEAD_TERMS`), а не с
номера записи в источнике: гейт близнецов принимает первого из пары, и пока
порядок был по номеру, `Apricots` побеждал `Avocados` с побайтово одинаковой
прозой. Список не может протухнуть молча — гейт требует, чтобы каждый термин
находил продукт в источнике.

| | было (строки) | стало (продукты) |
|---|---|---|
| единиц в корпусе | 658 строк | **466 продуктов** |
| страниц выпущено | 221 | **270** |
| снято гейтом близнецов | 381 | **164** |
| медиана сходства полного видимого текста | 0,376 | 0,383 |
| пар выше 0,70 по полному тексту | 12 | 17 |

(волна глубины опустила это до **0,137 по мерке гейта** при нуле пар выше порога и до **0,291 по всему `<body>`**, как мерил аудит, при одиннадцати парах выше 0,70 — обе мерки с точными числами в разделе «Объём берётся из имён, а не из воды»)

Последние две строки — честный замер, а не победа: **близнецы никуда не
делись у продуктов с одной ячейкой источника**, у которых источник даёт одну ячейку и
прозе нечего сказать (`cocoa ~ garam masala`, `bacon bits ~ soup mixes`). Это
не чинится слиянием и ждёт своей волны: различающего признака (что портится,
как это выглядит, что делать, когда срок вышел) у страницы пока нет.

## Главный урок этого сайта: проза была шаблоном

Первая сборка дала **593 страницы. Гейт близнецов оставил 5.**

Замер по 7 140 парам: медиана сходства **0,82**, девятый дециль **1,00** — побайтово одинаковый текст, 70% пар выше порога. Данные были настоящие, факты вычисленные, гейты на месте. И всё равно это был **один шаблон абзаца с подставленными числами** — дословно то, что Google называет *scaled content abuse*.

Вычисленные факты в заголовке от этого не спасают. Под ними стоял один и тот же скелет предложения.

### Что изменилось

`prose.py` сначала считает **форму данных**, а не их значения:

| Признак формы | Что меняет |
|---|---|
| меняется ли **единица** (дни → месяцы) при заморозке | «Freezing turns days into months» вместо «×4,3» |
| запрещена ли заморозка вовсе | заморозки нет — весь ответ в одной строке |
| какие из девяти ячеек источника заполнены | набор мест хранения выбирает рамку абзаца |
| где продукт в **распределении корпуса** | «больше, чем у 92% из 88» — проверяемое утверждение |
| кто стоит рядом в рубрике | имена соседей — самые непохожие слова на странице |
| ничья по сроку | «двадцать делят место» вместо выдуманного порядка |
| насколько широк разброс источника | «источник необычно неуверен» |

Тринадцать рамок ведущего абзаца, у каждой свой заголовок H2, плюс добавки, выбираемые по оставшимся сигналам. Итог по 25 651 паре выпущенных страниц:

| | было | стало |
|---|---|---|
| медиана сходства | 0,82 | **0,107** |
| девятый дециль | 1,00 | 0,27 |
| максимум | 1,00 | 0,700 |
| страниц прошло гейт | 5 | **221** |

(это замер той волны, на строках источника; после перехода на продукты их 270 — см. раздел о единице публикации выше.)

**Мера успеха — не сколько собрано, а сколько пережило гейты.** 593 собранные и 5 уникальных — это пять страниц, а не пятьсот девяносто три.

## Одна величина — одна функция

Аудит 05.09.2026 нашёл на этом сайте один дефект в шести обличьях. Число,
напечатанное в двух местах, приходило из двух РАЗНЫХ вычислений, а у отношения
никто не спрашивал направление — его подразумевало слово в шаблоне.

| Что печаталось | Где | Сколько |
|---|---|---|
| самое длинное окно вместо связывающего | 16 витрин | 401 строка |
| оптимистичный конец вместо ответа | указатель | 127 строк |
| два разных «во сколько раз» под одной подписью | бирка против прозы | 24 страницы |
| подпись называла не ту операцию | `30 days frozen ÷ 7 days open` под «What opening the package costs» | 9 страниц |
| деление на предел опасной зоны | `60 days frozen ÷ 0 days in the pantry` | 2 страницы |
| доля, округлившаяся в 0% | «keeps longer than 0% of everything listed» | 13 страниц |

Теперь у КАЖДОЙ величины ровно один носитель, и он назван:

| Величина | Функция | Кто печатает |
|---|---|---|
| связывающее окно (что кончится первым) | `prose.hot_slot` | бирка |
| ответ словами, осторожный конец | `prose.answer_value` | указатель, витрины, соседи, заголовок, описание |
| строка списка | `prose.listing_value` | все списки сайта |
| заголовок страницы | `prose.head_title` | `<title>` |
| выигрыш заморозки | `foodkeeper.freeze_gain` | бирка, проза, витрина, главная |
| цена вскрытия | `foodkeeper.opening_cost` | бирка, проза, витрина |
| цена тёплой полки | `foodkeeper.warm_cost` | бирка |
| кратность на бирке | `prose.headline_ratio` | `.cost` |
| подпись кратности | `prose.ratio_caption` | `.cost` |
| место в корпусе словами | `prose.corpus_place` | «Is that a long time?» |

Три правила, из которых это следует:

1. **Связывает то, что кончится первым.** Морозилка в кандидаты не идёт, пока
   есть окно вне её (замороженное при 0 °F безопасно сколько угодно), и
   сравниваются ОСТОРОЖНЫЕ концы диапазонов. Витрина печатает это же окно —
   и рядом самое длинное, когда оно ощутимо длиннее, потому что по нему
   построен рейтинг.
2. **У отношения спрашивают направление.** `fk.Ratio` — именованный кортеж
   `(r, den, num, den_key, num_key)`, где `r = num / den`. До этого две
   функции завели ПРОТИВОПОЛОЖНЫЕ соглашения: позиция «1» была знаменателем
   у одной и числителем у другой. Подпись выводится из тех же двух ячеек, что
   и число: «What the freezer buys you **over the sealed pantry**».
3. **Знаменатель не может быть пределом безопасности.** Ниже суток источник
   печатает не срок хранения, а предел пребывания в тепле: два часа для
   пирога, час для разведённой смеси. `fk._ratio` на таком знаменателе
   отказывает, и страница печатает раздел «Why this page prints no multiplier
   against the room-temperature figure» — отказ объявлен, а не спрятан.

## Нечисловой ответ — тоже ответ

`_parse_range` возвращал `None` на 63 ячейках, и страница после этого писала
«no pantry figure exists for it». Источник ОТВЕТИЛ:

| строка источника | ячеек | как печатается |
|---|---:|---|
| `Package use-by date` | 36 | Package use-by date |
| `Indefinitely` | 13 | Indefinitely |
| `When Ripe` | 12 | Until ripe |
| `1 Yea` (опечатка USDA) | 2 | Unreadable in the source |

`1 Yea` не читается как «1 Year»: дописать за USDA то, чего он не написал, —
это наше число, а не его. Печатается как непрочитанное, с исходной строкой.
На ПЯТОЙ нечисловой строке в новом снимке парсер падает (`UnknownCell`), а не
теряет её молча.

Читаются все ШЕСТЬ полей свободного текста (было три). Вместе с тремя
пропущенными терялась единственная настоящая инструкция по безопасности на
своей странице: «It is not safe to cook and eat a whole lobster if it is dead
at the time of preparation». Подсказки печатаются ПРОЗОЙ в разделе «What the
USDA adds in words»: 34 из них стояли в колонке величин, где `.rv` задаёт
капс, полужирный и правый край, и предложение в 321 знак набиралось как
величина.

## Облик: этикетка на банке, а не статья

Первый вариант сайта был статьёй: заголовок, врезка, колонка текста, таблица.
Дмытро посмотрел и сказал: «слабо по дизайну и типично, как предыдущий сайт».
Он был прав, и промах был ровно тем, что записан у нас в памяти как
**«уроки дизайна становятся близнецами»** — я перенёс на новый сайт РЕШЕНИЕ
прошлого (набор токенов, тёмная тема, типографская шкала), а не УРОК.

Поэтому дальше — по правилу D-014: сперва письменный список «что уже занято»
(что мы уже сделали на MileageCurve и FedPay и повторять нельзя), потом
**четыре цельных направления** от четырёх независимых исполнителей, каждое со
своей главной и своей страницей продукта, и выбор глазами. Все четыре лежат в
`research/design-2026-09/`.

02.09.2026 было выбрано направление **«бирка на банке»**, и сайт свёрстан им
целиком. **15.09.2026 владелец посмотрел все четыре и выбрал другое —
«Дата, а не срок»**, назвав причину: навигация и удобство. Сайт переодет.
Заметим для протокола: у выбранного направления был САМЫЙ НИЗКИЙ балл жюри
(6,8 против 7,8 у бирки). Жюри оценивало страницу, владелец выбирал прибор —
и балл оказался не решением, ровно как и было записано на витрине.

Действующее направление — **«Дата, а не срок»**. Оно не украшение, а набор
запретов:

| Правило облика | Что оно запрещает |
|---|---|
| **та же ячейка до и после ввода** (`.out`) | у ответа НЕТ второй копии: до ввода в ячейке срок источника, после — дата на том же месте и тем же кеглем. Прежняя бирка печатала срок дважды (крупно в `.dur` и ещё раз в `.out`), и это делало страницу списком, а не прибором |
| порядок **имя → поле даты → ответ** | поле не прячется внутри ответа: на бирке оно лежало третьей строкой снизу, и до него не доходил взгляд |
| **срок источника не исчезает** | после ввода он сжимается в подпись рядом с обратным отсчётом («5 days from today · 1 week»), а не пропадает: это единственное число на сайте, которое не наше |
| **один сигнал, и он КРАСКА** | сигналом набрана величина, ради которой построена страница, в её окончательном виде: у товара — дата, у рейтинга — ведущее значение. Заливки в облике нет вовсе |
| **два регистра кегля** | капитель прописными — только подпись, НАЗЫВАЮЩАЯ соседнюю величину. Первый прогон одел капителью запрос, отсчёт и оговорку: вышло семь строк прописных против двух величин, то есть подпись стала основным текстом |
| **три веса линейки** | 7px наверху страницы — сам предмет; 2px — граница «ответ кончился»; 1px — строка реестра. Четвёртого веса нет |
| **два вертикальных края на весь сайт** | имя по левому, величина по правому, колонка величины фиксирована `18rem` с 640px — иначе правый край гулял бы вслед за длиной имени, и краёв стало бы столько же, сколько страниц |
| **ни одной рамки вокруг данных** | рамка означает ВВОД, и носят её ровно два элемента: поле даты и поле поиска |
| у каждого отсчёта **своё** поле даты | «от покупки» нельзя считать от дня вскрытия; одно общее поле уже стоило нам 323 строк, посчитанных не от того дня |
| под датой печатается **вердикт словами** | «Past it by 5 days» / «28 days from today» — голая дата не отвечает на вопрос, с которым пришли (прививка от проигравшего направления «циферблат») |
| таблиц нет вовсе | величина — это **поле** или **строка реестра**: подпись, значение |
| **одна база отступа** `--u:4px` | ни одного padding, margin, gap или top, набранного руками: всё есть `calc(var(--u)*n)` |
| **шесть кеглей**, основной 15px | ниже 15px живёт только капитель подписей (12px) |

Что переезд стоил и что он вскрыл (15.09.2026):

| Находка | Замер | Что сделано |
|---|---|---|
| гейт контраста искал токены исчезнувшей заливки | `--on-signal`, `--sig-cap`, `--sig-hair` | **гейт упал сам**, на «нет переменной», а не позеленел молча. Пары переписаны под новые роли: сигнал стал ТЕКСТОМ, и порог для него 4,5:1, а не 3:1; пар стало 13 вместо 12 |
| ответ перестал влезать на экран телефона | 10 страниц из 295 выше 553px, худшая 574,5 | самое длинное окно уехало НИЖЕ границы, к кратности: это сравнение, а не ответ, и стоило 113px первого экрана. Стало: худшая **546,5**, медиана 454,7, выше бюджета **0** |
| класс «посчитано» не влезал в потолок кода | 4654 при потолке 4608 | потолок НЕ поднят: `document` и `getAttribute` названы в скрипте по одному разу, приставка `data-` ушла в помощник. Стало 4585 |
| «tear here», «the window on the label», «the signal field on this page» | 320 / 85 / 283 страниц | четыре английские строки переписаны; слово «label» в отданном тексте осталось только там, где оно принадлежит ИСТОЧНИКУ (USDA про этикетку продукта) |

### Разбор облика 05.09.2026 и что из него вышло

Это разбор ПРЕЖНЕГО направления («бирка»). Оставлен как история: половина его
находок — свойства системы, а не бирки, и они перенесены в новый облик
(одна база отступа, шкала кеглей, веса линейки со своим фоном, величина как
число, расчёт высоты по отданной разметке).

### Разбор облика 05.09.2026 и что из него вышло

Отдельный разбор (`_research/audit-2026-09/design-two-sites.md`, раздел 2)
нашёл три блокера и восемь важных. Направление тогда осталось тем же — это
была та же бирка на банке; чинилось то, что её **не существовало** на
половине экранов.

| Находка | Замер | Что сделано |
|---|---|---|
| **B1** 448 строк списка вне списка на 221 из 221 страниц товара | браузер рисовал их точками-маркерами: ни пунктира, ни правого края | обёртка вернулась прошлой волной, **гейт появился этой**: `<li>` без списка-предка роняет сборку, и поломка на это есть |
| **B2** отрывного корешка нет на десктопе, а колонка бирки — 1400px белого | 46% ширины экрана на 1280px | лист стал ДВУМЯ предметами на столешнице: `align-items:start` (бирка кончается вместе с содержимым, под ней стол), перфорация — настоящая насечка `--tear` в 10:1 вместо пунктира в 1,69:1 |
| **B3** «на один экран» сторожил `len(name) > 48` | 230 страниц из 299 выше бюджета, худшая **902px** при 553 | линейка `design.label_height` считает высоту по ОТДАННОЙ разметке и ОТДАННОМУ CSS; ступень кегля выбирает ширина строки в Arial; кратность и рельса уехали под перфорацию. Замер в браузере: **0 из 277 выше 553px, худшая 530** |

### Что при переносе облика нашлось такого, чего гейты не видели

Смена облика — лучший стресс-тест для проверок. Она вскрыла **три гейта,
переставших запускаться молча**, и два дефекта, которых не было ни у кого в
списке:

| Находка | Как она пряталась |
|---|---|
| «одна величина — одно имя» искала `<p class="lead">` и `<td>` | ни того, ни другого на странице уже нет — гейт печатал «пройден», не сверив ни одной величины |
| «числа в прозе» считала строки `<tr><th>` | таблиц стало ноль, и условие `if m3 and rows` **выключило проверку ровно тогда, когда список исчез** |
| «у каждого отсчёта своё поле» читала `<td data-lo=…>` | ячейка стала `<span>` — та же немота |
| **два поля с одним `id`** на странице | поле для отсчёта печаталось и на бирке, и в корешке; `getElementById` возвращает первый, второй `<label for>` указывает в никуда. Нашла **самопроверка**: поломка «переименуй поле» не покраснела |
| **408 упоминаний таблицы** на сайте без единой таблицы | все гейты читают РАЗМЕТКУ, а врал ТЕКСТ: «Give the table the day it went into storage» |
| **девять страниц обещали выигрыш морозилки при отношении ≤ 1** | «0.2 times longer than the refrigerator» там, где морозилка держит вшестеро меньше. Нашёл гейт согласования, расширенный с глаголов на существительные: сперва «1 times longer», за ней — вся семья |

Из первых трёх вышло правило, которое теперь держит **три новых гейта**:

* **«слова совпадают с разметкой»** — читает ВИДИМЫЙ текст (без `style` и
  `script`, иначе `text-align:right` считается словом «right») и требует: если
  страница говорит «таблица», «столбец» или «график» — эта разметка на ней
  обязана быть;
* **«id не повторяется на странице»** — класс брака, который видно только в
  браузере;
* **«числа в README совпадают со сборкой»** — за один сеанс мне пришлось
  править вручную четыре числа в этом самом файле; каждое было верным в день,
  когда его написали.

## Что на странице считается, а не переписывается

FoodKeeper печатает до девяти диапазонов на продукт и молчит обо всём остальном. Вычисляем:

- **выигрыш заморозки** — отношение двух диапазонов (100 выпущенных страниц); источник печатает оба и никогда не делит одно на другое;
- **цена вскрытия** — сколько теряет вскрытая упаковка (73 страницы);
- **место в рубрике** — с ничьими, делящими место;
- **положение в корпусе** — процентиль, чтобы «много» было проверяемым;
- **разброс внутри диапазона** и **разброс между способами** — это разные величины: первая про неуверенность источника, вторая про то, насколько важен выбор способа;
- **дата вместо срока** — календарь считает в браузере, без сети.

Страница заводится, если источник даёт продукту хотя бы один срок вне морозилки и находится хотя бы три соседа **по данным**. Вычисленные величины решают не «быть ли странице», а сколько на ней блоков сравнения: порог `MIN_FACTS` прореживает их и больше ничего не снимает. Остальное не выпускается, а не наполняется водой.

## Три окна абзаца, и ни одно не про «побольше слов»

- **35–72 слова** — блоки, которые ОТВЕЧАЮТ на запрос. Единица извлечения в поиске — пассаж, а не страница.
- **18–56 слов** — блоки, которые лишь ВВОДЯТ стоящие ниже строки бланка.
- **80–140 слов** — блоки ГЛУБИНЫ: они называют другие продукты поимённо, и требовать от них краткости значило бы выбросить имена.

Требовать сорок слов от подводки — значит требовать воды, а вода у всех страниц одинаковая. Раздутые подводки давали 70–82% общих пятёрок слов.

Окно спрашивается **одной функцией** `prose.window_for(h2, атрибуты)`. Пока таблица окон стояла в `render.py`, а её копия под именем `INTRO_HINT` — в `gates.py`, это были две лестницы для одной величины; третье окно развело их на первом же прогоне — двадцать абзацев мерились чужим окном. Перечисляющий абзац помечен **в разметке** (`data-win="detail"`), а не именем заголовка: заголовок полки называет саму полку и у каждой рубрики свой.

## Объём берётся из имён, а не из воды

PLAYBOOK §1 требует 1 500–4 000 слов на той же странице; аудит намерил **медиану 705 и ноль страниц из 242** над порогом. Ловушка при этом записана в том же PLAYBOOK: дописывание слов — ровно то, чем ферма получила 593 страницы с медианой сходства 0,82, которые Google отказался индексировать.

Объём взят из четырёх блоков, каждый из которых **ветвится по форме данных** и **называет другие продукты поимённо**:

| Блок | Признак формы, по которому выбирается рамка | Что называет |
|---|---|---|
| Products the USDA rates in the same places | размер когорты с ТЕМ ЖЕ набором ячеек: 0 / 1–3 / 4–15 / 16+ | имена когорты, ближайшие по сроку |
| The rest of the … shelf | размер полки и край: 1 / 2–4 / верх / низ / середина | верх и низ полки, середина, ближайшие |
| If it has to keep longer than this | есть ли куда шагнуть вверх: нет / ≤4 / много | шаг вверх и его величина, обратное направление |
| The record this page is built from | сколько строк источника под именем: 1 / 2–4 / 5+ | номера записей, ячейки словами, ключевые слова |

Замер по 43 660 парам выпущенных страниц (296 страниц товаров). Мерок две, и
называть их одним словом нельзя: **гейт** сравнивает страницу минус
объявленное общее (`render.page_text`), **аудит** мерил весь `<body>` целиком,
вместе с общим хвостом в 653 слова из 1 780. Второе число всегда выше просто
потому, что треть страницы у всех одинакова по построению:

| | аудит до волны | сейчас |
|---|---|---|
| медиана слов на странице товара (весь `<body>`) | 705 | **1 754** |
| страниц ≥ 1 500 слов | 0 из 242 | **296 из 296** |
| из них своего текста (минус объявленное общее) | 578 | **1 127** |
| сходство по мерке ГЕЙТА, числа участвуют: медиана / макс | — | **0,137 / 0,649** |
| сходство по мерке ГЕЙТА, скелет: медиана / макс | — | **0,163 / 0,672** |
| сходство своей прозы: медиана / макс | — | **0,152 / 0,6997** |
| весь `<body>`, как мерил аудит: медиана / макс | 0,382 / 0,807 | **0,291 / 0,747** |
| пар ≥ 0,70 по всему `<body>` | 15 из 24 310 | **11 из 43 660** |
| пар ≥ 0,95 по скелету | 0 | **0** |
| выпущено страниц | 242 (221 товар) | **320 (296 товаров)** |

Одиннадцать оставшихся пар по мерке аудита названы поимённо и не спрятаны:
`grapes ~ papaya` 0,747, `arugula ~ celery root` 0,743, `arugula ~ rhubarb`,
`guacamole ~ main dishes`, `kohlrabi ~ zucchini`, `bagel ~ macaroons` (0,807 у
аудита), `beef ~ veal`, `veal ~ venison`, `cheese curds ~ yogurt`, `fatty fish
~ lean fish`, `ground turkey ~ stuffed raw chicken breasts`. Это продукты с
ОДИНАКОВЫМ окном на ОДНОЙ полке источника: у них совпадают и соседи, и шаг
вверх, потому что совпадают данные, а треть страницы у всех одинакова по
построению. Развести их дальше можно только выдумав разницу, которой в
источнике нет. Гейт держит порог на своей мерке, а это число стоит здесь,
чтобы следующий замер начинался не с нуля и чтобы никто не выдал одну мерку
за другую.

Сходство упало, пока страница росла вдвое, — потому что росли **имена**. Числа занимают в абзаце единицы процентов, имена — десятки, и список когорты у каждой страницы свой: он отсортирован по близости к ЕЁ сроку.

## Близнецы меряются по ВСЕЙ странице, и мерок три

Гейт мерил `own_prose` — первый абзац под каждым непостоянным H2, около двухсот слов из тысячи семисот. Пара «bagel, fresh baked ~ macaroons, french» расходилась двумя фразами: **0,81 по полному видимому тексту и 0,68 по прозе**. Мера, которая смотрит на восьмую часть страницы, — не мера страницы.

Теперь `render.page_text` даёт весь видимый текст минус **ровно то, что объявлено общим**: три общих раздела (`prose.CONSTANT_HEADS`), фразы банка (`<span data-std>`), подвал (`data-shared` и `.foot`) и ссылка «к содержимому». Навигация, подписи полей, величины, строки списков и заголовки **остаются**: страница, у которой совпало всё, кроме прозы, — близнец.

| Мерка | Что спрашивает | Порог |
|---|---|---|
| своя проза | пишем ли мы всем одно и то же | 0,70 |
| вся страница, числа участвуют | одинаково ли выглядит отданное | 0,70 |
| вся страница, скелет без чисел | не один ли это шаблон с подставленными значениями | 0,95 |

Отбор при сборке считает **ровно те же три**: иначе сборка выпускала бы то, что гейт снимет. Пустая выборка у любой из мерок — провал, а не «пройден»: все три держатся на разметке, а разметку переписывает любая перевёрстка.

## Счёт отвечает на тот вопрос, который произнесён

`no pantry figure exists for it, as for 132 of the 466 foods` стояло на **63 страницах**. 132 — число продуктов с набором РОВНО {холодильник, морозилка}; продуктов **без срока в кладовой** — 222. Число было верным и отвечало на вдвое более узкий вопрос, чем задан фразой. То же на 8 страницах про «пропускает холодильник»: 16 против 126.

Счёт теперь берётся **по предикату, который произносит предложение** (`ctx["no_place"]`), а гейт `счёт отвечает на своё утверждение` пересчитывает каждое такое утверждение по его собственному предикату — и **краснеет, если объявленной фразы вообще нет в сборке**: переписанная фраза, мимо которой проверка стала промахиваться, — это гейт, переставший запускаться.

## Написание американское, и это гейт, а не дисциплина

Аудит нашёл `neighbour(s)` 223 раза на 223 страницах, `behaviour` 104 раза, `recognise` 37 раз — на сайте, у которого единственный рынок США. В отданном их больше нет ни одного; словарь гейта расширен с 16 образцов до **58** (`len(gates.BRITISH)`, посчитано, а не вспомнено: здесь уже стояло «47») и покрывает то, что на сайте про еду появится первым: `mould`, `yoghurt`, `aluminium`, `pasteurise`, `caramelise`, `sulphur`, `fibre`, плюс окончание `-isation` целиком. `-ised` и `-ising` в словарь НЕ вошли намеренно: `compromised`, `advertising` и `arising` стоят в сборке и написаны по-американски — проверено по отданному, а не по памяти.

## Одна величина — одна функция

Срок вне морозилки печатался в семнадцати местах. Пока это делали две независимые лестницы порогов, в бланке стояло «1 month», а в абзаце про то же самое — «4 weeks», и рядом кратность 4,3, посчитанная по тем же данным. Все три числа были формально верны.

Теперь единица берётся **из источника** (`item["units"][ячейка]`), а `scale_of` спрашивает ту же `human`, а не собственные пороги. Точка входа одна: `shelf_h(товар)`.

## Окно значит одно из двух, и слова у них разные

`They are quality guidance, not a safety test` стояло на **221 странице
сразу**. На 54 из них это недопредупреждение: предел холодильника у
скоропортящегося — граница безопасности, а не вкуса. На 97 — перепуг:
морозильное число говорит только о качестве, потому что при 0 °F еда остаётся
безопасной сколько угодно, и сайт этого не сказал ни разу (`indefinit` —
ноль вхождений). Одна рамка на два противоположных последствия: ферма
шлёпнулась об это на MileageCurve («покажет не то, а не откажет» для 7% и для
700%») и на BatteryCross.

Теперь предложения ДВА, и между ними выбирает **`fk.window_kind(товар,
ячейка, верх)`** — одна функция, четыре ветки, каждая опирается на то, что
источник напечатал сам:

| Ячейка | Вид | Почему так |
|---|---|---|
| короче суток | **безопасность** | это не срок хранения, а предел пребывания в тепле: 2 часа у пирога, 1 час у разведённой смеси |
| морозилка | **качество** | при 0 °F еда безопасна, пока заморожена; портится только вкус |
| шкаф | **качество** | если USDA вообще оценивает комнатную температуру, продукт при ней стабилен |
| холодильник | **безопасность** у скоропортящегося, **качество** у прочего | рубрика источника: мясо, птица, рыба, молочное с яйцами, готовая еда, детское питание, растительные белки, замороженная покупка, охлаждённое тесто |

Ровно эту границу подтверждает сам источник в подсказке к соевому соусу:
«Quality, not safety, is the reason the labels on these products suggest that
they be refrigerated after opening». Раньше эта подсказка набиралась капсом по
правому краю в колонке величин.

Слово стоит **на бирке, над перфорацией** (`.means`) и разворачивается в
раздел `Is this window about safety or about taste?`. Подвал сайта и
`/terms/` больше не решают за строку: они отсылают к странице, где решение
принято по данным.

## «Срок вышел — а теперь что?»

Самый дорогой запрос ниши, и сайт не отвечал на него **ничем**: календарь
печатал `Past it by 6 days` и замолкал. По видимому тексту 242 страниц:
`throw away` / `discard` — 0, `when in doubt` — 0, `danger zone` — 0,
`overnight` — 0, `reheat` — 0.

Появилось два носителя:

* раздел **`It is past the date. Now what?`** на каждой странице товара —
  ветвится по виду окна: под пределом безопасности стоит «выброси, не пробуя»
  и правило двух часов, под окном качества — по чему судить. «Понюхай и
  реши» под пределом безопасности не печатается НИКОГДА: две рамки на одно
  последствие, и читатель выберет разрешающую;
* страница **`/past-the-date/`** — правило целиком: два вида окна с
  посчитанными долями корпуса, ночь на столе (2 часа, 1 час выше 90 °F,
  диапазон 40–140 °F), почему пробовать — не проверка, и где кончается ответ
  источника.

**По чему судить — словами своей рубрики.** «По чему судить» было ОДНОЙ
фразой на все 209 страниц окна качества, и она называла вздутую, помятую и
проржавевшую банку — на 133 страницах, где банки нет вовсе: 58 свежих овощей
и фруктов, 40 выпечки и муки, 21 напиток. Число верное, слова чужие: та самая
«одна рамка на разные последствия». Теперь фраз **шесть**, и выбирает между
ними рубрика источника (`prose.LOOK_BY_CAT`, таблица ПОЛНАЯ — запасного
варианта нет, новая рубрика в снимке обязана уронить сборку):

| Фраза | Рубрики | Страниц |
|---|---|---:|
| свежее: плесень, слизь, мягкие или потемневшие пятна, кислый запах | Produce, Dairy & Eggs, Meat, Poultry, Seafood, Deli, Baby Food, Frozen, Vegetarian Proteins | 60 |
| кладовая: прогорклый запах у ореха, масла и семени, плесень на горлышке, вздутая банка | Shelf Stable Foods | 47 |
| выпечка: плесень забирает всю упаковку, а не ломоть; затхлое или старое масло в муке и смеси | Baked Goods | 40 |
| банка и банка-стекло: вздутая, текущая или ржавая уходит невскрытой | Condiments, Sauces & Canned Goods | 29 |
| напиток: газ, которого не должно быть, муть, нити, кислый запах | Beverages | 21 |
| сухое: жучки и паутина в пакете, затхлый или прогорклый запах, слипание от сырости | Grains, Beans & Pasta | 12 |

Ни одна из шести не говорит «понюхай и реши»: все шесть называют признаки, при
которых еда уходит В МУСОР независимо от даты, и обратной стороны — «пахнет
нормально, значит можно» — нет ни в одной. Под пределом безопасности не
печатается ни одна. Гейт `страница говорит, что делать дальше` проверяет ОБЕ
стороны — стоит своя и не стоит ни одной чужой, — а рубрику берёт у продукта
сам и смотрит в объявленную таблицу, а не спрашивает у функции, которая эту
фразу и выбрала.

**Чего в снимке нет — то названо чужим.** FoodKeeper печатает сроки и больше
ничего: ни указания выбросить, ни правила двух часов вне тех пяти коротких
ячеек. Всё, что за пределами снимка, подписано как руководство USDA и её
FSIS, а не как разобранная нами строка, и округ ответственности назван прямо.
Двухчасовое правило при этом не взято с потолка: источник печатает его
**внутри этого же набора**, пятью ячейками короче суток (пироги, киш,
разведённая смесь), и страница считает их, а не вспоминает.

## Сигналом помечено связывающее окно, а не худший выбор места

`hot_slot` брал минимум по всем ячейкам, и на **48 страницах** это оказывалось
не «что кончится первым», а «куда не надо было класть»: у картошки светился
холодильник (1–2 недели) при шкафе на 1–2 месяца — на странице, где сам
источник пишет, что от холодильника картошка темнеет при варке и сластит.

Третье правило отбора: **ячейка короче суток — это предел пребывания в тепле,
а не окно хранения.** «2 Hours» у пирога значит «не оставляй на столе», и
ответом на «сколько пирог лежит» это быть не может: `/pies/` и `/quiche/`
отвечали двумя часами при недельном и пятидневном холодильном окне того же
вида. Правило снимается, когда деться некуда — если другого окна вне
морозилки у вида нет, предел остаётся ответом. Сам предел не пропадает: его
называет «а теперь что» и раздел про отказ от кратности.

Четвёртое правило отбора: **ячейка, у которой в ТОМ ЖЕ состоянии и при том же
вскрытии есть место с более длинным окном, не связывает никого.** Проигравшее
место не выбрасывается, а называется в разделе «Two places, and one of them is
the wrong one»: молча снять строку значило бы спрятать половину источника.
Гейт пересчитывает оба правила руками, отдельно от генератора.

## За какой вид говорит страница: значение объявлено, а не выведено

Страница живёт по ПРОСТОМУ слову — `/eggs/`, `/tuna/`, `/milk/` — и говорить
обязана за тот вид, который человек имеет в виду, набирая это слово. Вывести
его из подзаголовка не получается ничем: словесная лестница («подзаголовок не
сужает продукт до консервированной формы») дала **тринадцать страниц**, которые
говорили за чужой вид и при этом печатали фразу «за страницу отвечает первая
строка источника» — на них неверную. У молока первой строкой стоит `plain or
flavored`, у тунца человек имеет в виду консерву, у арахисовой пасты —
магазинную.

Поэтому значение объявлено таблицей `fk.PLAIN_MEANS`: по строке на имя, и
объявлен КЛЮЧ СТРОКИ ИСТОЧНИКА, а не число. Сроки по-прежнему приходят из
снимка. Имя, у которого в снимке больше одной строки и нет объявления, роняет
сборку.

Второй ответ таблицы — `SPLIT`: простое слово не значит одного вида. `Beef` —
это и фарш, и стейк, и рёбрышки; `Ham` — двадцать видов; `Pies` — три начинки
с разными окнами. Такая страница **не выбирает вид молча**: у неё нет ни
одного числа крупной строкой, вместо ответа стоит поле выбора — виды,
сгруппированные по окну, короткое сверху, — и она говорит словами, почему
одного числа тут нет. Своих ячеек у такого продукта нет вовсе: ни кратности,
ни места в рубрике, ни даты — всё это утверждения про вид.

Третий случай — вид, который простое слово значит, а источник оставил без
окна вне морозилки: у обычного молока вместо холодильного срока напечатано
`Package use-by date`. Страница печатает этот ответ словами и рядом — виды,
которым источник срок дал.

Оговорка про более короткий вид («Shorter under the same name: Raw whites,
yolks keeps 2 days») стои́т **под ответом**, а не над ним. Пока она стояла
подписью под именем продукта, первым числом страницы `/eggs/` были два дня
сырого белка — то самое, от чего оговорка и должна была уберечь. Гейт
«сказанное о выборе вида совпадает с видом» проверяет и порядок, и согласие
фразы с подписью поля.

## Общая фраза объявлена, а не размазана

Указание «выброси, не пробуя» обязано звучать **одинаково** везде, где стоит:
писать одно последствие каждый раз новыми словами — ровно тот дефект, за
который ферма платила. Но гейт близнецов считает пятёрки слов, и сто общих
слов на страницу уронили корпус с **270 до 143**.

Поэтому общие фразы объявлены списком (`prose.STD_BANK`), печатаются
внутри `<span data-std>` и не участвуют в сравнении на близнецов. Пометка — не
лазейка, потому что закрыта с **обеих** сторон и с потолком:

* внутри пометки — только фраза из банка;
* фраза из банка вне пометки — тоже провал (иначе она вернулась бы в
  сравнение и уронила страницу);
* объявленная и нигде не напечатанная — рычаг, которого нет;
* больше трети видимых слов страницы под пометкой — это и есть
  страница-шаблон, и сборка краснеет.

## Поиск и навигация — на КАЖДОЙ странице

Замерено по прежней сборке, а не предположено: поле поиска стояло на **1
странице из 242**, и ещё 241 страница несла его стили без единого узла
разметки. Ни одна страница товара не вела ни в свою рубрику, ни на витрину:
`TOP_LINKS` был объявлен в генераторе и не отрисован нигде. Ссылок внутрь
сайта вело на `/contact/` — 462, на `/longest-keeping/` — одна. Человек,
пришедший из выдачи на страницу еды, не мог посмотреть НИЧЕГО другого.

Что стоит теперь первым блоком корешка, сразу под ответом, на всех 301
странице:

| строка | что это | откуда берётся |
|---|---|---|
| поле поиска | лукап по всему сайту | строит скрипт; указатель лежит в странице |
| «Every food on this site, one page» | замена поиска без скрипта | статическая ссылка, на `/all/` не печатается |
| **In this aisle** | ВВЕРХ, в рубрику | `cat_slug`, только если витрина рубрики существует |
| **Close by name or shelf** | ВБОК, до четырёх еды | `render.pick_related` |
| **Rankings** | три витрины | `render.TOP_LINKS`, текущая страница вычёркивается |

Рубрика на кромке (`Dairy Products & Eggs · USDA FoodKeeper`) перестала быть
мёртвым текстом и стала ссылкой.

**Вбок — два разных родства вперемежку.** По слову ИМЕНИ (не по ключевым
словам источника: по ним «Milk» роднился с «Ham» через `canned`) и по полке.
Порознь ни одно не годится: по слову у молока выходят одни «X milk», по полке
— маргарин и сыр, которых и так шесть штук в блоке соседей. Ближайшие
`NEIGHBOURS[1]` по полке из списка вычеркнуты — иначе одна и та же ссылка
стояла бы на странице дважды под разными подписями. Замер: 257 страниц из 277
несут четыре хода вбок, 5 — ни одного (у их рубрики просто нет других страниц
за вычетом соседей), и пустая строка тогда не печатается вовсе.

## Поиск режется на слова, а не склеивается в одну строку

Прежний поиск удалял из запроса пробелы и искал подстроку в так же склеенном
имени. Порядок слов у FoodKeeper обратный тому, которым говорят, и результат
был такой:

| набрано | что было | что стало |
|---|---|---|
| `olive oil` | ничего | Almond oil, Coconut oil, Frying oil, Olives |
| `salmon` | **Roasted nuts (peanuts, cashews, almonds)** — в склейке `cashewsalmonds` сидит `salmon` | Salmon |
| `chiken` | ничего | Chicken, Chicken parts, Chicken salad |
| `eggs` | ничего | Eggs, Egg substitutes |
| `how long does milk last` | ничего | Milk |

Правила, каждое куплено замером на собранном сайте:

1. Запрос режется на слова; совпадение считается по КАЖДОМУ слову, счёт —
   сумма. Точное слово 5, слово-начало 4, слово длиннее найденного не больше
   чем на три буквы 3 (это и есть множественное число: `eggs` → `Egg`),
   опечатка в одну букву 2, подстрока 1.
2. Опечатка не трогает первую букву: без этого `olive` находил `live` в
   «Fresh whole lobster, live».
3. Диакритика складывается (`NFD`): `creme` находит `crème`, `consomme` —
   `consommé`.
4. Точное начало ИМЕНИ идёт первым: `milk` — это «Milk», а не «Coconut milk»,
   хотя слово совпало у обоих.
5. Слова-обрамления запроса (`how long does … last`) объявлены в `FIND_STOP` и
   уезжают в разметку атрибутом `data-stop`: без них `does` находил «Hot dogs»
   по опечатке в одну букву. Слова живут в разметке, а не в скрипте.
6. В строке результата печатается СОБСТВЕННОЕ имя продукта, даже когда совпало
   чужое: `mayo` показывает «Mayonnaise, commercial», а не «mayo».

Строка указателя — одна на ПРОДУКТ, четыре поля: имя, адрес, величина, другие
имена. Прежде строка была на каждое имя (1325 строк) и склеивалась по ключу
без разделителей, поэтому `deli meat` уводил на один продукт из трёх, у
которых это имя есть.

**Цена.** Указатель — 52 КБ на страницу, и он стоит на каждой. Медиана
страницы: 74 КБ отданных, **20 КБ в gzip**. Это цена поиска, который не делает
ни одного сетевого запроса; загрузить указатель отдельным файлом означало бы
нарушить правило «готовая страница не ходит наружу».

## Контрол без скрипта — не мёртвый контрол

С выключенными скриптами прежняя страница показывала живое на вид поле даты и
подпись **PICK THE DAY ABOVE**, которая не сбывалась никогда, а главная —
поле поиска, которое не искало, и объяснение к нему стояло с атрибутом
`hidden`. Описанный и несуществующий рычаг хуже отсутствующего.

Правило: **каждый контрол строит скрипт**, а в разметке на его месте стоит то,
что работает без скрипта.

| контрол | без скрипта | со скриптом |
|---|---|---|
| поле поиска | ссылка «Every food on this site, one page» | поле + список находок; ссылка остаётся |
| поле даты | коробка спрятана `hidden`, в ответе стоит сам диапазон: «4 days to 6 days after the day you stored it» | поле даты; ответ становится «Past it by 1 day · Sat 5 Sep – Mon 7 Sep» |

Проверено в браузере на `sandbox="allow-same-origin"` (скрипты выключены): в
отданном **ноль** `input`, `button`, `select` и `textarea` на всех 301
странице, и это держит гейт «мёртвых контролов нет».

## Заголовок — тот вопрос, которым эту страницу ищут

Замерено по прежней сборке: «how long» не стояло ни в одном заголовке, слово
«last» встречалось во всём корпусе **один раз**, `<h1>` был голым именем
источника на 218 страницах из 221. Головной запрос ниши — «how long does X
last in the fridge».

```
ITEM
HOW LONG DOES          ← 11px
COOKED RICE            ← крупная строка: короткое имя
LAST IN THE FRIDGE?    ← 11px, место называет ТО САМОЕ окно ниже
USDA FOODKEEPER: ...   ← полное имя источника, если оно длиннее
```

Крупной строкой остаётся имя: вопрос, набранный тем же кеглем, добавил бы к
первому экрану три строки заглавных. Хвост вопроса называет место
связывающего окна (`ASK_WHERE`), а не общее «last?» на 277 страницах — иначе
это было бы ключевое слово, а не вопрос.

**Короткое имя** (`render.assign_short`) — имя источника до первой запятой,
и только если обрубок остаётся различающим по всему корпусу: «Shrimp,
crayfish» и «Shrimp, shellfish» обязаны остаться разными заголовками.
Сокращаются 28 имён из 466, у 10 сокращение отменено столкновением. Замер на
телефоне: `<h1>` был 197px (семь строк заглавных) на банке консервов, стал
**66px на всех страницах**, а полное имя печатается строкой ниже целиком —
выброшенный хвост имени это выброшенное различие.

**Глагол согласуется с именем.** 66 описаний в выдаче читались «How long
Apples keeps in the fridge», четыре рубрики — «How long meat keep». Одна
функция (`prose.does_do` / `prose.keeps_word`), и гейт проверяет её СВОИМ
правилом, а не спрашивая у неё же.

## Первое крупное число — связывающее

Замер на телефоне: на банке консервов первым крупным числом стояло «2 YEARS TO
5 YEARS» — запечатанная банка в шкафу, — а «3 DAYS TO 4 DAYS» вскрытой банки
стояло ниже. Взгляд ловит первое крупное число, и оно обязано быть тем,
которое кончится первым. Поля бирки идут теперь так: **что → сигнальное окно →
самое длинное окно → кратность**.

`gates.py` получает **словарь отданных файлов** и больше ничего — намерения генератора ему недоступны.

| Гейт | Чем куплен |

| нет управляющих байтов | эскейп трижды за сеанс стал управляющим байтом |

| нет страниц-сирот | страница без входящей ссылки не индексируется |

## Волна «браузер действительно не ходит наружу» (06.09.2026)

Верификатор вложил в готовую страницу `<img src="//evil.example.com/p.gif">` и
прогнал все проверки: **красных ноль из 69**. Восемь несущих сразу — тоже
одна красная, и та случайная (гейт внутренних ссылок споткнулся о preload).
Гейт, названный «браузер не ходит наружу», отчитывался «выборка 11 212 внешних
адресов» и оставался зелёным. Собственный контроль у него при этом РАБОТАЛ:
`<img src="https://evil…">` он ловил. **Гейт с рабочим контролем, мимо
которого проходит настоящий случай, — это зелёный свет, а не полугейт.**

Замер по тридцати пяти способам утащить браузер: **ловилось пять**. Мимо шли
протокол-относительные `img`, `iframe`, `link`, `url()` и даже
`<script src="//evil">`, а сверх того `srcset`, `action`, `poster`,
`object data`, `ping`, `imagesrcset`, `xlink:href`, `formaction`, `base`,
`meta refresh`, `srcdoc`, `@import` голой строкой и `fetch()` в теле скрипта.

Причина — **одна строка**: в списке разрешённых НАЧАЛ стоял «/», а начало «/»
совпадает и с «//». Это ровно записанный урок фермы «проверять надо всё, за
чем браузер пойдёт»: тогда гейт искал `http://` и `https://` и не заметил
`src` вообще без схемы.

**Что сделано.** Несущие объявлены ОДИН раз — `render.FETCH_CARRIERS`,
двадцать девять строк, собранных по перечню URL-несущих атрибутов HTML.
Оттуда читают трое: сканер гейта, абзац приватности (число печатается из
длины таблицы) и рукописная таблица поломок. Списка начал больше нет: форма
адреса разбирается по частям, «//» отсекается ДО «/», а сравнение идёт по
ОРИГИНУ целиком — `https://keepsuntil.com.evil.example.com` не наш хост.
Разметка читается разбором тегов, поэтому `src='//x'` и `src=//x` видны так
же, как `src="//x"`. Внутрь `data:` и `srcdoc` гейт заходит: объявление
`xmlns` запросом не считается, а спрятанный `<image href=…>` — считается.

**Два новых гейта.** «Каждая объявленная несущая сканируется» — на каждый
ключ собирается крошечная страница с чужим адресом, и сканер обязан её
увидеть; ключ, добавленный в объявление и не прочитанный кодом, роняет
сборку. «Свой ресурс существует» — путь в `src`, `poster`, `data`, `url()`
обязан вести на существующий файл: гейт внутренних ссылок читал только
`href`, то есть путь ЧЕЛОВЕКА, а битая картинка молчаливее битой ссылки.

**Заодно закрыто того же вида.** Политика приватности сверялась с одним
`<script src>` — одной несущей из двадцати девяти; теперь со всеми, и число
несущих она печатает из того же объявления. `g_scripts` и гейт внутренних
ссылок читали атрибуты регуляркой на двойные кавычки — переведены на разбор.
Вердикт «безопасность или вкус» проверялся только на страницах товара, а
запрета печатать его в другом месте не было — теперь область объявлена.
`pure_selftest` получил известные ответы `_fetch_verdict` (включая тот самый
`//evil`), разбору атрибутов, `url()`/`@import`, `prose.human`,
`answer_value` и направлению кратности — 145 ответов вместо 78.

**Одна поломка перестала ломать, и самопроверка это поймала.** Старая
поломка «гейт ослеп» переименовывала три вещи (`href=`, `src=`, `url(`) и
слепила ровно тот гейт, который только их и читал; расширенный гейт после неё
продолжал видеть `content` у `meta`, выборка не пустела, и он зеленел на
слепом сайте. Теперь список берётся из объявления. **Поломка, тихо
переставшая ломать, — тот же дефект, что гейт, тихо переставший запускаться.**

## Волна «развернуть то, что развернёт браузер» (08.09.2026)

Верификатор ударил по той же таблице третий раз. Шестнадцать несущих прошлой
волны закрыты честно — каждая краснеет минимум на двух гейтах, — но **четверо
уходили целыми, при 75 гейтах и ни одном красном**. Все четверо одного вида:
**гейт читал обёртку, а не нагрузку, или не считал носитель носителем**.

| проход | почему прошёл | чем закрыт |
|---|---|---|
| `data:image/svg+xml;base64,…` с чужим `href` внутри | `_data_verdict` снимал проценты и мнемоники и **не снимал base64**: метки честно просматривали base64-текст и честно ничего не находили. ТА ЖЕ нагрузка в процентах ловилась — один гейт доказывал и умысел, и свой обход | развёртка всего, что развернёт браузер: проценты, мнемоники, base64 и base64url, **рекурсивно** — `data:` вкладывается в `data:` |
| `onclick="fetch('//чужой')"` | приёмы сети применялись к телу `<script>` и к отданному `.js`. Атрибут-обработчик **не был несущей вообще**: чтобы вынести запрос со страницы, хватало перенести его на три слова левее | несущая `on_event`: имя атрибута объявляется НАЧАЛОМ (`on*`), потому что обработчики — не список, а открытое семейство |
| `onmouseover="location='//чужой'"` | та же причина. Это тот самый случай, который собственная строка гейта называет «хуже картинки: уезжает не запрос, а читатель» | та же несущая; значение атрибута прогоняется по всей таблице приёмов сети |
| `<object><param value="//чужой">` | значение параметра несущей объявлено не было | несущая `param_value`: разобрать, какой параметр адрес, нечем — значит, своим путём обязан быть ЛЮБОЙ |

**Тот же вопрос, заданный ещё раз** («что ещё браузер исполняет или по чему
ещё он идёт, чего в таблице нет»), дал ещё три:

* `<script type="speculationrules">` — браузер уходит по этим адресам **сам и
  заранее, до клика**. Родня карты модулей, и пропущена была ровно потому же;
* `report-uri` в политике безопасности — адрес, по которому браузер стучит
  сам. Отдельная ирония: политику эта же волна и добавляет, и **средство
  против счётчиков умеет быть счётчиком**;
* SMIL: `<animate attributeName="href" to="//чужой">` — адрес приезжает в
  чужой атрибут ПОСЛЕ загрузки, а в разметке лежит с самого начала.

Несущих стало **35**, и у каждой новой своя поломка в самопроверке — включая
`base64` внутри `base64`, где на первом уровне не срабатывает ни одна метка и
запрос находится только второй развёрткой.

### Подпорка: политика безопасности содержимого

Гейт доказывает, что **наш генератор** ничего наружу не уводит. Он не может
доказать, что туда ничего не допишет **платформа**, — а у этой фермы
Cloudflare однажды дописал скрипт на 164 страницы ПОСЛЕ двадцати трёх зелёных
гейтов. Обещание страницы приватности («откройте панель сети — там один
запрос») держалось на честном слове ровно в той части, которую мы не
контролируем.

На каждой странице теперь стоит `<meta http-equiv="Content-Security-Policy">`,
собранная из объявления `render.CSP_POLICY` и из кусков ЭТОЙ ЖЕ страницы:

```
default-src 'none'; base-uri 'none'; form-action 'none';
script-src 'sha256-…'; style-src 'sha256-…'; img-src data:
```

**Хэш, а не `'unsafe-inline'` и не `'self'`.** Дописанный хостом скрипт бывает
двух видов: встроенный (его пустило бы `'unsafe-inline'`) и файлом с нашего же
оригина, `/cdn-cgi/…` (его пустило бы `'self'`). Оба закрыты перечислением
хэшей ровно тех кусков, которые собрала сборка.

**Новый гейт «политика безопасности закрывает несущие»** держит политику и
таблицу несущих вместе, чтобы они не разошлись молча:

* политика есть на каждой странице и ровно одна; страниц ноль — провал;
* директивы, их порядок и источники совпадают с объявлением, а хэши
  **пересчитываются из СОБРАННОЙ страницы**. Именно этим строгая политика
  дважды молча убивала счётчик на этой ферме: хэш, посчитанный до последней
  подстановки, теперь роняет сборку, а не выключает скрипт в браузере
  читателя;
* в объявлении нет ни одного источника из `CSP_FORBIDDEN` и ни одной
  директивы, которую браузер в `<meta>` игнорирует (`frame-ancestors`,
  `sandbox`, `report-uri`): рычаг, которого нет, хуже отсутствующего;
* **каждый** ключ `FETCH_CARRIERS` назван в `CSP_GOVERNS` — либо директивой,
  которая его держит, либо честным «политике не подчиняется» с причиной.
  Таких шесть, и главная из них `meta refresh`: политика его не
  останавливает, и держит его один сканер. Несущая, добавленная в таблицу и
  не названная здесь, роняет сборку.

**Проверено в браузере, а не в выводе сборки** — записанный урок фермы. Чистая
вкладка, `http://localhost:8822/`:

* консоль **пуста**, панель сети — **один запрос, сама страница**;
* собственный скрипт страницы **выполнился**: он сам создаёт поле `#ku-q`,
  поле есть, запрос «chee» даёт 8 попаданий, первое — Cheese; на странице
  товара слушатель календаря пересчитал дату по `change`;
* политика **действует**: встроенный скрипт, дописанный в готовую страницу,
  отказан («Executing inline script violates …»), скрипт файлом со СВОЕГО
  оригина отказан, картинка не из `data:` отказана. Это ровно три способа,
  которыми хост дописывает страницу.

### Вторая сторона гейта политики

Сторона «разметка → политика» была полной. Сторона «политика → разметка»
состояла из фраз, вписанных в гейт руками, — и это половина проверки: перепиши
абзац другими словами, и «отрицания на странице нет» гейт прочтёт как
«отрицать нечего» и позеленеет ровно тогда, когда обещание перестанет быть
напечатанным. Ферма это уже проходила: перевёрстка обесточила три гейта, и все
три позеленели.

Обещания объявлены теперь один раз в `render.PRIVACY_CLAIMS` (шесть строк),
страница печатается оттуда же, а сверка идёт **равенством**: фраза стоит на
странице тогда и только тогда, когда сборка её держит. Обещание, которого
сборка не держит, — обман читателя; обещание, которое сборка держит, а
страница уже не печатает, — выключенная проверка. Обе поломки написаны.

| проход | почему прошёл | замер |
|---|---|---|
| `image-set("//evil" 1x)` | строка объявления НАЗЫВАЛА image-set, а код искал одно `url(`; голая строка скобок не содержит | 3 записи: в элементе `style`, в атрибуте с `&quot;` и с одинарной кавычкой |
| `import x from "//evil"` | регулярка знала `import(` со скобкой; у статического импорта скобки нет | +`export … from`, +`import "адрес"` |

| `&quot;` внутри атрибута `style` | значение атрибута браузер получает расшифрованным, гейт — нет | расшифровка перед разбором |

**И шестое, крупнее всех: ОБЛАСТЬ.** Гейт читал `_html(files)` — только

**непрочитанными**, а непрочитанный файл выглядит ровно как чистый. Виды
отданных файлов объявлены теперь в `render.SERVED_KINDS` (семь строк:
`.html` разметкой, `.css` стилем, `.js` приёмами сети, `.svg` разметкой,
`.xml`/`.txt`/`.json` адресами в тексте), расширение вне объявления **роняет
сборку**, и на каждый вид есть своя поломка.

**Новый гейт** «каждый отданный файл разобран по своему виду» сверяет
объявление и выкладку в обе стороны и на каждом виде проверяет пробником, что
чужой адрес получает отказ. Гейтов стало **75**.

**Выборка считается по видам файлов.** Поломка «сканер ослеп на все несущие»
**перестала ломать** ровно тогда, когда гейт вышел за `.html`: разметка
молчала, а карта сайта и robots держали общую цифру непустой. Это третий
случай тихо переставшей ломать поломки на этом сайте, и лечится он не
поломкой, а гейтом — он обязан назвать выборку ОТДЕЛЬНО по каждому виду:

```
пройден браузер не ходит наружу · выборка 11531 мест ухода наружу в файлах
вида «markup», 320 мест ухода наружу в файлах вида «urls»
```

**Обещание приватности печатается из ПОСЧИТАННОГО.** Раньше абзац говорил
«столько-то способов, какими страница HTML умеет увести браузер» — это
утверждение о HTML, которого никто не считал: одна строка `src` покрывает
десяток элементов. Считаны две ДРУГИЕ величины, и обещание теперь ровно про
них: «the 30 kinds of address-carrying construct an HTML page can hold …
the scan reads every file in the release, in all 7 file formats it knows, not the pages alone». Оба
числа печатаются из объявлений и оба сверяются гейтом политики.

**Замер после правки — независимой атакой, не самопроверкой.** 94 вектора,
написанных по перечню URL-несущих атрибутов HTML: 86 в разметке (включая
`base`, `ping`, `usemap`, `longdesc`, `profile`, `manifest`, `dynsrc`,
`srcdoc`, `@namespace`, `cursor:url()`, обратные слэши, мнемоники, отсутствие
кавычек и похожий домен) и 8 файлами вне `.html`. **Пропущено ноль.**
Контроль на месте: чистая страница зелёная, пустая выкладка красная.

## Волна «починить сами гейты» (06.09.2026)

Аудит нашёл дефекты, каждый из которых прошёл мимо тридцати зелёных проверок,
и назвал причину: **27 гейтов из 30 не проверяли, что они вообще на что-то
посмотрели**. Эта волна чинила не сайт, а систему проверок.

### 1. Пустая выборка краснеет — теперь по построению

`_seen(n, что)` не только возвращает провал при нуле, но и **объявляет размер
выборки**. `run` печатает его рядом с «пройден» и — главное — **считает
провалом зелёный гейт, который выборку не назвал ни разу**. Пока это правило
держалось на памяти того, кто пишет следующий гейт, оно и не держалось:

```
пройден строки имён сверены с источником · выборка 6542 строк с именем
пройден близнецы по всему видимому тексту · выборка 638 полных текстов главного элемента
```

Охрана появилась у **24 гейтов**, у которых её не было вовсе: язык страницы,
управляющие байты, двойное экранирование, скрипты (два гейта), голова
страницы, внутренние ссылки, сироты, карта сайта, robots, политика, «одна
величина — одно имя», классы (два гейта), числа README, слова против разметки,
id, ссылки на себя, согласование числа со словом, числа в прозе, размер
рекламных мест, контраст, источник, сверка выкладки с генератором.

### 2. Область гейта — часть гейта

| гейт | было | стало |
|---|---|---|
| одна величина — одно имя | страницы С МЕТКОЙ `page-type=product` | страницы, которые ПЕЧАТАЮТ величину на бирке: потерянная метка больше не выводит страницу из-под правила |
| написание американское | видимый текст | видимый текст **и атрибуты** — описание в выдаче, `alt`, `aria-label`, подсказки: британское слово в описании не видно ни одному текстовому гейту |
| близнецы | свой текст, по типам страниц | **плюс новый гейт** по ПОЛНОМУ видимому тексту главного элемента, все типы страниц |
| поиск | «каждая строка ведёт на существующее» | **плюс новый гейт**: у каждой выпущенной страницы есть строка, и сопоставитель к ней приводит |

### 3. Гейт, согласный сам с собой

Гейт, который берёт ожидаемое значение у той же функции, что напечатала
проверяемое, остаётся зелёным, когда функцию ломают. Таких связок здесь
нашлось шесть, и все они настоящие: `render.jaccard/shingles/shingles_num`
меряют близнецов И отбирают корпус; `render.page_text` решает, что вообще
сравнивается; `design.text_width/line_count` выбирают кегль крупной строки И
проверяют высоту бирки; `foodkeeper._parse_range/_ratio` — единственные разбор
и деление; `prose.mult` печатает кратность И сверяется с ней.

Лечение — не «не звать функцию» (тогда гейт станет второй реализацией и
разойдётся молча), а **известные ответы, написанные руками**: `pure_selftest`,
78 случаев. Три из них с первого прогона показали, что ошибалась ПРОВЕРКА, а
не функция (перестановка букв стоит двух правок, а не одной), — это ровно то,
чего от известных ответов и ждут.

### 4. Гейт внутри условия, которое он охраняет

* `рекламные места стоят по объявлению` — охрана выборки стояла ВНУТРИ
  `if rd.ADS`: при выключенной рекламе гейт печатал «пройден», не посмотрев ни
  на одну страницу. Теперь страницы считаются всегда, места — когда реклама
  объявлена включённой.
* `числа в прозе совпадают с сайтом` — пропавшая витрина выключала проверку
  строкой `if not page: continue`. Теперь отсутствие витрины и есть провал.

### 5. Шесть новых гейтов

| гейт | что ловит | поломок |
|---|---|---:|
| близнецы по всему видимому тексту | пару, разошедшуюся прозой и совпавшую всем остальным; область — ВСЕ типы страниц | 3 |
| сроки заголовка и описания стоят величиной | срок в `<title>` или описании, которого нет ни в одном поле страницы: единственный текст, который человек читает ДО перехода, и единственный, мимо которого шли все текстовые гейты | 3 |
| части строки бланка стоят в строке | `rk`/`rv` вне строки, строку с одной половиной, подпись поля вне поля — сиротство сигнатурного приёма, которое `<li>`-гейт не видит | 4 |
| молчание источника подтверждено источником | «no pantry figure exists for it» при непустой СЫРОЙ ячейке — и обратное: ячейку с числом, потерянную разбором | 3 |
| реклама не налезает и не обрезана | место внутри места, выход из потока, необъявленного обрезателя, две клетки сетки на одно место | 5 |
| поиск находит каждую выпущенную страницу | страницу без строки указателя и строку, к которой сопоставитель не приводит: сопоставитель переписан на питоне по `FINDER_JS` | 3 |

### 6. Порог мерки по всему главному элементу, и откуда он взялся

`MAIN_TWIN_MAX = 0.80` — не подогнанное число. Замер 06.09.2026, худшая пара
(`grapes ~ papaya…`): **0,6491** по своему тексту и **0,7452** по всему
главному элементу; вклад объявленного общего хвоста — **0,096**. Потолок =
0,70 своего текста + этот вклад. Скелетный потолок остался 0,95: это другой
вопрос — «не один ли это шаблон с подставленными значениями».

Измеренное сейчас: по главному элементу с числами максимум **0,7452**
(8 пар выше 0,70, все ниже 0,80), по скелету **0,7672** при потолке 0,95;
у витрин 0,4218 и 0,4593, у правовых 0,3534 и 0,3464.

**Названное ограничение.** Отбор корпуса в `render.py` считает три мерки
(своя проза, вся страница с числами, скелет) и НЕ считает четвёртую: во время
отбора страница ещё не одета в оболочку, и главного элемента у неё нет. Запас
до потолка — 0,055. Если корпус когда-нибудь дорастёт до него, гейт покраснеет
раньше, чем это уедет наружу, но лекарством будет пересборка корпуса, а не
правка порога.

## Сайт, который может нести рекламу, — и говорит об этом правду

До этой волны реклама была **запрещена собственными гейтами**: `ADS = False`,
единственное объявленное место 728x90 жило в колонке шириной 439–598px и
обрезалось на 18–42% при `overflow:hidden`, а проверка размера начиналась с
чтения того же флага, что и то, что она проверяет. Плюс страница приватности
отрицала ровно то, что нужно запуску.

**Три места, и каждое влезает в свой контейнер на каждой ширине:**

| Место | Где стоит | Размеры |
|---|---|---|
| `ad-rail` | последнее поле бирки, то есть ПОСЛЕ ответа | 300x50 · 320x50 · **300x600** в боковой колонке с 1024px |
| `ad-flow` | в потоке корешка, ниже перфорации и ниже четырёх разделов | 300x250 · **336x280** |
| `ad-lead` | полосой во всю ширину под листом | 300x250 · 336x280 · 728x90 · **970x250** |

Правила, каждое купленное ошибкой:

1. **Ни одного пустого места.** Пока сеть не подключена, каждое место занято
   НАШЕЙ врезкой со ссылкой вглубь сайта и подписью «From KeepsUntil». Пустая
   серая коробка с надписью «Advertisement» стоит на 322 страницах соседнего
   сайта; узел, спрятанный стилем, остаётся ребёнком и ломает правила
   «последний теряет линию» — 540 невидимых мест сломали пять правил на 157
   страницах другого.
2. **Ответ выше первой рекламы на каждом типе страницы.** У товара реклама
   начинается после всей бирки (ответ, кратность, поле даты); у витрины и
   главной — только полосой под листом. Это отдельный гейт.
3. **Рельса на телефоне — полоса в 50px, а не прямоугольник в 280.** Она
   стоит в бирке, а бирка обязана помещаться на один экран: замер показал,
   что 336x280 уводит отрывную линию с 648 на 928 пикселей. Оба требуемых
   прямоугольника 336x280 стоят ниже линии.
4. **Размер проверяется расчётом, а не CSS против CSS.** Гейт считает ширину
   контейнера на тринадцати ширинах экрана по числам облика (поле 10/24px,
   бирка 520px, лист 1120px, две колонки с 1024px) и сверяет с объявленным
   размером. Двухколоночный режим поэтому начинается с 1024px, а не с 900:
   между ними корешок сжимался до 332px, и 336x280 в него не влезал.
5. **Правовые страницы и 404 рекламы не несут вовсе.**

Внешнего тега в выкладке НЕТ: `AD_NETWORK = None`, и готовая страница
по-прежнему делает ноль сетевых запросов. Но запрета больше нет —
`g_no_external` и `g_scripts` читают объявленный список адресов сети, и обе
ветки проверены самопроверкой на синтетических страницах. Чтобы включить
сеть, нужно ровно три значения: `AD_NETWORK`, `AD_CLIENT`, `AD_UNITS`.

## Политика описывает то, что грузит браузер, и сверяется в ОБЕ стороны

Прежний гейт умел только «сказано «нет» — значит, не должно быть». Он молчал
бы в обратном случае: реклама и счётчик приезжают в разметку, а политика
продолжает их отрицать. Теперь:

* отрицание обязано быть правдой обо ВСЕЙ выкладке;
* всё, что выкладка несёт, обязано быть НАЗВАНО в политике;
* **обещанное и несуществующее — тоже провал**: флаг `ANALYTICS` переписывает
  страницу и не ставит ни одного скрипта, то есть сам по себе он рычаг,
  которого нет. Дёрнувший его получает красную сборку, а не читатель —
  обещание.

Отдельным абзацем — то, что делает хост: обфускация почты у Cloudflare
переписывает КАЖДЫЙ найденный адрес и дописывает свой скрипт, и это уже
случилось на студийном сайте. Поэтому адрес почты стоит на **двух** страницах
вместо 302, и оба переключателя Cloudflare выключаются до выкладки.

**Побайтовой сверки отданного с собранным на сайте НЕТ, и обещать её нельзя.**
Она стояла на `/privacy/` фразой «every release is compared byte for byte
against the files the build produced» — как доказательство предыдущего
заверения, через двоеточие, — и не существовала: в `build.yml` девять шагов, и
«Rebuild must be byte-identical» сличает локальную пересборку с локальной
сборкой, а не отданную страницу с собранной. Ложное проверяемое утверждение в
правовом документе. Вычеркнуто 16.09.2026; осталось то, что правда, — оба
переключателя выключены, а дописанное хостом запрещает политика, посчитанная
ХЭШЕМ от того самого кода, который ушёл в страницу. Вернуть фразу можно будет
только вместе с десятым шагом, который после выкладки тянет отданные страницы
и диффит их с `dist`.

Ноль строк схемы и ноль карточек на 242 страницах — при том, что
единственный рычаг роста ветки это ссылки. Поставлено:

| Тип страницы | Схема |
|---|---|

украшение сниппета, а обман. Картинки в карточке нет намеренно: у сайта нет
ни одной, а адрес несуществующей — и ложь, и внешний запрос.

## Отбор считается до неподвижной точки

Страница ссылается только на выпущенные соседей, но выпущены не все: гейт близнецов снимает часть уже **после** того, как на них сослались. Первая версия дала 20 ссылок в никуда.

Круг повторяется, пока состав не перестанет меняться (сейчас 3 круга). В неподвижную точку входит и список рубрик: рубрика, потерявшая страницы, опускается ниже порога хаба, а хлебная крошка на него уже ссылается. Оба множества только сокращаются — сходимость гарантирована.

**Источник не отдаётся скрипту**: `urllib` получает 403 и с браузерными заголовками тоже. Файл берётся браузером по адресу, найденному в сетевых запросах самой страницы FoodKeeper. Поэтому обновление — ручной шаг (`fetch_data.py --manual` печатает процедуру), а CI ничего не качает и запускает только `--verify`.

Это не обходной путь, а правильная схема: сборка обязана быть воспроизводимой и не зависеть от чужого сервера в момент выкладки, а на каждой странице стоит дата снимка. Автоматически обновляющийся источник тихо переписал бы весь корпус под чужие цифры.

## Файлы

| Файл | Что делает |
|---|---|
| `foodkeeper.py` | разбор источника и **вычисленные** величины, которых в нём нет |
| `prose.py` | проза, ветвящаяся по форме данных; тринадцать рамок, добавки, окна абзаца |
| `render.py` | оболочка страницы, витрины, юридические страницы, карта, отбор до сходимости |
| `gates.py` | 74 гейта по собранному + отпечаток содержимого |
| `fetch_data.py` | провенанс данных и процедура обновления |
| `dist/` | 331 файл на выкладку |

Проверено в браузере на 1280 и 375 пикселях: горизонтального переполнения нет, консоль чиста, календарь считает (1 сентября + 30 дней = 1 октября).
